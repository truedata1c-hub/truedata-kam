# PharmaCheck · Переговоры — инструкция по эксплуатации

Для того, кто отвечает за сервер. Первоначальная установка стенда описана в [`deploy/README.md`](../deploy/README.md); здесь — как модуль работает, обновляется, резервируется и восстанавливается.

## 1. Из чего состоит

Docker Compose project `truedata-kam` в каталоге `/opt/truedata/kam`:

| Сервис | Что делает |
| --- | --- |
| `db` | PostgreSQL 16, схема `kam`. Данные — `${KAM_DATA_DIR}/pgdata` |
| `api` | Модуль (Node.js): API, интерфейс, сквозной вход, очередь писем, напоминания, ежечасная очистка служебных таблиц. Файлы документов — `${KAM_DATA_DIR}/files` |
| `backup` | Ежедневные резервные копии в `${KAM_DATA_DIR}/backups` |

`KAM_DATA_DIR` на стенде — `/srv/truedata-mdm/kam` (диск данных MDM). Маршрут и сертификат выдаёт Traefik сервера (сеть `coolify`). Секреты — только в `/opt/truedata/kam/.env`, в Git их нет.

Проверка состояния: `https://<адрес>/healthz` → `{"ok":true,"version":"v0.5.0"}`.

## 2. Переменные `.env`

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_PASSWORD` | Пароль базы |
| `KAM_HOST`, `APP_URL` | Адрес модуля; `APP_URL` — для ссылок в письмах |
| `KAM_DATA_DIR` | Каталог данных: `pgdata`, `files`, `backups` |
| `SSO_PUBLIC_KEY`, `SSO_ISSUER`, `SSO_AUDIENCE` | Сквозной вход из платформы (открытый ключ Ed25519, издатель и адресат токена) |
| `FRAME_ANCESTORS` | Адреса платформы, которым разрешено встраивать модуль |
| `SSO_DEMO_PRIVATE_KEY`, `DEMO_PLATFORM_PASSWORD` | Демо-платформа `/demo-platform` (только стенд) |
| `KAM_DEMO_PASSWORD`, `DEMO_AUTO_UPGRADE` | Пароль демо-пользователей; при `1` демо-набор пересоздаётся, если в новой версии он изменился (только стенд; у реального клиента — `0`) |
| `BACKUP_AT`, `BACKUP_KEEP_DAYS` | Время ежедневной копии (по Москве, по умолчанию `03:15`) и срок хранения дампов (14 дней) |
| `SETTINGS_KEY` | Ключ шифрования секретов клиента (пароль SMTP): `openssl rand -base64 32`. Хранить только в `.env`; без него пароль SMTP хранится открытым текстом. При смене ключа администратору нужно заново ввести пароль SMTP |
| `APP_TIMEZONE` | Часовой пояс модуля для «сегодня», сроков, просрочек и замещений (по умолчанию `Europe/Moscow`) |

После правки `.env`: `cd /opt/truedata/kam && docker compose --env-file .env up -d`.

## 3. Обновление и откат

Выпуск — из GitHub: ветка `release/vX.Y.Z` (или тег `vX.Y.Z`, или ручной запуск workflow `deploy`). Workflow прогоняет тесты, собирает образ, передаёт его на сервер, и `kam-deploy`:

1. проверяет свободное место и каталог данных;
2. берёт `compose.yaml` из того же образа (код и конфигурация не расходятся);
3. поднимает новую версию и ждёт `healthy`;
4. если версия не поднялась — возвращает прежний образ и прежний `compose.yaml`.

Миграции базы применяются при старте `api` и только добавляют. Откат кода после миграции безопасен: старая версия не использует новые таблицы.

Ручной откат на конкретную версию: перезапустить workflow `deploy` для нужной ветки `release/…`.

## 4. Резервные копии

Служба `backup` каждую ночь:

- снимает дамп базы `pg_dump -Fc` в `backups/db/kam-ГГГГММДД-ЧЧММСС.dump` и сразу проверяет, что он читается (`pg_restore -l`);
- дополняет зеркало файлов документов `backups/files` (файлы хранятся по SHA-256 и не меняются, поэтому копируются только новые);
- удаляет дампы старше `BACKUP_KEEP_DAYS`;
- пишет итог в `backups/status.json`.

Администратор клиента видит состояние в «Настройки переговоров → Настройки → Резервные копии»: время и размер последней копии, предупреждение, если копии старше суток или последняя попытка не удалась.

Копия вне расписания:

```sh
cd /opt/truedata/kam
docker compose --env-file .env exec backup touch /backups/.now   # копия начнётся в течение минуты
docker compose --env-file .env logs --tail 20 backup
```

Копии лежат на том же сервере. Для защиты от потери сервера каталог `backups` нужно регулярно забирать на другое хранилище (например, `rsync` по расписанию на резервный сервер или в объектное хранилище).

## 5. Восстановление

Проверено на копии демо-набора: восстановленная база совпала с исходной по числу кампаний, ячеек разбивки, шагов согласования, уведомлений и документов; зеркало файлов — побайтно.

```sh
cd /opt/truedata/kam
DUMP=/srv/truedata-mdm/kam/backups/db/kam-20261118-031500.dump    # нужный дамп

# 1. Остановить модуль (база остаётся работать)
docker compose --env-file .env stop api

# 2. Восстановить базу целиком одной транзакцией: при ошибке ничего не меняется
docker compose --env-file .env exec -T db pg_restore -U kam -d kam --clean --if-exists --single-transaction --no-owner < "$DUMP"

# 3. Вернуть файлы документов, если каталог files потерян или повреждён
rsync -a /srv/truedata-mdm/kam/backups/files/ /srv/truedata-mdm/kam/files/
chown -R 1000:1000 /srv/truedata-mdm/kam/files

# 4. Запустить модуль и проверить
docker compose --env-file .env start api
curl -s https://kam.demo.truedata.tech/healthz
```

Если сервер потерян полностью: установить стенд по `deploy/README.md`, перенести `.env` и каталог `backups`, выполнить шаги 2–4. Восстановление на другой базе для проверки копии: `createdb kam_check && pg_restore --no-owner -d kam_check "$DUMP"`.

## 6. Почта

Письма отправляет `api` через SMTP клиента, который администратор подключает в «Настройки → Почтовый канал». Пока сервер не подключён, письма копятся в очереди со статусом «канал не настроен»; после подключения уходят в течение минуты. Ошибка отправки — повтор через 1, 2, 4, 8 и 16 минут, затем «не доставлено» с ручным повтором в журнале писем. Пароль SMTP хранится в базе клиента и в интерфейс не возвращается.

С сервера должен быть открыт исходящий доступ к SMTP клиента (порт 587 или 465).

## 7. Журналы и диагностика

```sh
cd /opt/truedata/kam
docker compose --env-file .env ps
docker compose --env-file .env logs --tail 100 api      # запросы, ошибки, очередь писем, напоминания
docker compose --env-file .env logs --tail 50 backup
```

Каждая ошибка API возвращает `request_id`; по нему ищется строка в журнале `api`. Действия пользователей — в «Журнале изменений» модуля (неизменяемый).

## 8. Обслуживание стенда

- Пересоздать демо-набор: `docker compose --env-file .env exec -e KAM_PASSWORD='<пароль>' api node dist/src/cli.js seed-demo --reset`.
- Заблокировать пользователя: `docker compose --env-file .env exec api node dist/src/cli.js disable-user <email>`; сменить пароль: `docker compose --env-file .env exec -e KAM_PASSWORD='<пароль>' api node dist/src/cli.js set-password <email>`.
- Новый клиент и его первый администратор: `… cli.js create-client <код> <название>`, `KAM_PASSWORD=… create-user <email> <имя>`, `grant-admin <email> <код>`. Дальше всё настраивает администратор в интерфейсе (см. [ADMIN.md](ADMIN.md)).
- Место на диске: база демо — единицы мегабайт; дамп ~0,3 МБ; файлы документов — по объёму загрузок (до 50 МБ на файл).

## Очистка служебных таблиц

Модуль раз в час удаляет: истёкшие сессии (через сутки), ключи повтора команд (через 30 дней), попытки входа и использованные токены сквозного входа (через сутки), прочитанные уведомления (через 180 дней) и непрочитанные (через год), завершённые письма — отправленные, недоставленные и устаревшие (через 180 дней). Журнал изменений, история кампаний, версии и документы не удаляются никогда. Сроки — в `src/housekeeping.ts`.
