# PharmaCheck · Переговоры

Модуль переговорных кампаний КАМ с аптечными сетями: портфель кампаний, версии предложения, гибкий маршрут внутреннего согласования, подтверждение сетью и финальные условия. Рынок — Россия, контур PharmaCheck. Для заказчика модуль — раздел «Переговоры» в меню PharmaCheck: платформа встраивает его в свою страницу и открывает сквозным входом.

Поведение задаёт ТЗ: `docs/TZ.md` (копия; канонический документ — заметка «KAM-Negotiations-TZ» в Obsidian, проект Юнифарм). Архитектура, оформление и порядок выпуска повторяют серверную MDM (`truedata1c-hub/truedata-mdm`).

## Запуск для разработки

Нужны Node.js 22 и PostgreSQL 16.

```sh
npm ci
export DATABASE_URL=postgresql://postgres@localhost:5432/kam
npm run migrate
KAM_PASSWORD='не-короче-10-символов' npm run admin -- seed-demo   # демо-клиент DEMO, 14 сотрудников, ~80 кампаний
npm run dev
```

Сервис слушает порт 8080; API — `/api/kam/v1`, состояние — `/healthz`. Интерфейс: `cd web && npm ci && npm run dev` (Vite проксирует API на 8080) или `npm run build` — тогда собранный `web/dist` отдаёт сам сервис.

Демо-пользователи: `<имя>@demo.truedata.tech` с паролем из `KAM_PASSWORD` — например `anna.smirnova` (КАМ), `elena.sokolova` (руководитель КАМ), `olga.morozova` (национальный руководитель), `igor.vasiliev` (финансовый директор), `admin` (администратор). Пересоздать набор: `seed-demo --reset`.

## Сквозной вход: что делает платформа

1. В меню PharmaCheck — пункт «Переговоры»; страница содержит `<iframe>` на адрес модуля.
2. По клику сервер платформы выпускает JWT, подписанный EdDSA (Ed25519), сроком не более 2 минут:

   ```json
   { "iss": "truedata-platform", "aud": "pharmacheck-kam", "sub": "<id пользователя в платформе>",
     "email": "user@company.ru", "name": "Имя Фамилия", "client": "<код компании в модуле>",
     "iat": 1700000000, "exp": 1700000060, "jti": "<уникальный id>" }
   ```

3. Встроенное окно открывает `https://<адрес модуля>/sso?embed=1&token=<JWT>`. Модуль проверяет подпись открытым ключом платформы (`SSO_PUBLIC_KEY`), срок, издателя, адресата и одноразовость `jti`, создаёт сессию и открывает рабочую область без своего меню.
4. Модуль сообщает платформе заголовок страницы для хлебных крошек: `postMessage({ type: 'kam:title', title })`.

Новый пользователь создаётся при первом входе без ролей; роли, руководителя и сети назначает администратор модуля. Встраивание разрешено только адресам из `FRAME_ANCESTORS`. Модуль и платформа должны быть на одном домене второго уровня (`*.truedata.tech`), иначе браузеры не сохранят cookie во встроенном окне.

Пока платформа не подключена, страница `/demo-platform` (пароль стенда) имитирует её: выбор пользователя платформы выпускает такой же токен и открывает модуль во встроенном окне.

## Устройство

| Путь | Назначение |
| --- | --- |
| `migrations/` | SQL-миграции схемы `kam`; применяются при старте |
| `src/access.ts` | Полномочия и области видимости ролей, подчинённые, видимость кампаний |
| `src/campaigns.ts` | Портфель, карточка, создание, правка, переходы этапов |
| `src/admin.ts` | Роли, сотрудники и оргструктура, закрепление за сетями, сети и ИНН, бренды, типы кампаний, журнал |
| `src/sso.ts`, `src/demoPlatform.ts` | Сквозной вход и демо-платформа |
| `src/commands.ts` | Идемпотентность, ревизия кампании (`If-Match`), журнал в одной транзакции с изменением |
| `src/demo.ts`, `src/cli.ts` | Демо-набор и администрирование стенда |
| `web/` | Интерфейс Vue 3 + Quasar в оболочке TrueData / PharmaCheck |
| `deploy/` | Стенд на VPS рядом с MDM, скрипт выпуска с откатом |

## Отступления и оговорки

- Справочники сетей и брендов ведутся в модуле; при появлении доменов MDM («Компании и сети», «Препараты») модуль будет читать их оттуда.
- Суммы в версиях (шаг 2) — «сумма, ₽» без признака НДС: правило учёта не определено (ТЗ §12).
